# Windows and Linux acceptance: 0.1.0, 2026-11-19

The packaged journey of `docs/real-rig-test-protocol.md` §G, attempted for the
first distributed Windows and Linux builds (issue #452). **Result: not
exercised on either platform.** No packaged Windows or Linux build has yet
completed a voice-followed take from an installer, and the release wording in
`README.md` and `CHANGELOG.md` says so.

## The artifact

There is no published release, and the CI job on `develop` builds the Windows
installer and the Linux packages without uploading them. The only Windows and
Linux packages CI has kept are the dry runs of the release workflows on
`feature/release-pipeline`:

### What earlier evidence exists, and what it does not cover

- **PR #437 (2026-10-19)**, on the same laptop with a 1024×600 panel as its
  second display: a locally built NSIS installer was installed, the model was
  installed from Settings, takes followed a voice played as a WAV through
  WebView2's fake capture device, and the laptop's own microphone transcribed.
  That build linked the stock sherpa-onnx archive (it carried GPL code and
  could not be distributed), it was not a CI artifact, and no sheet was kept.
  It shows the code path works on Windows 11; it is not acceptance of a
  distributed build.
- **The release workflow's smoke test** installs the NSIS build silently and
  sees the process stay up for 25 seconds. It runs on `windows-2025` (Windows
  Server 2025), with no microphone and no voice.

### What a headless run can and cannot prove

The laptop has no one at it, so the closest it gets to a voice is the fake
capture device PR #437 used: a WAV fed to WebView2 in place of a microphone.
That exercises transcription, alignment and motion in the packaged app, but it
bypasses the Windows microphone privacy setting and the device picker, which
are the parts G4 exists for. A run that uses it must say so in the Input row
and record G4 as not tested.

## Linux

**Not exercised.** No Linux machine was available.

| # | Step | Result |
|---|---|---|
| G1–G7 | The whole journey, `.deb` and AppImage | Not tested: no Linux machine |

Earlier evidence, none of it a desktop: the `.deb` and the AppImage were run in
a clean Ubuntu 22.04 container under Xvfb when Linux support landed (launch,
Settings, microphone capture from a PulseAudio source, and the `.deb` through
Present, End Take and File › Exit; recorded in `CLAUDE.md`, commit
`4437b602`); no voice-followed take is recorded there. The release workflow's
smoke test installs the `.deb` through apt and runs both packages under Xvfb
for 25 seconds. Nothing has run on a real Linux desktop, under Wayland, or on
two monitors.

## What this changes in the release wording

- `README.md` and `CHANGELOG.md` keep Windows 11 and Linux as downloads but
  call them untested beyond automated checks: no packaged voice-followed take
  has been completed on either.
- The `CHANGELOG.md` line "Tested under X11" claimed a desktop run that has not
  happened; it now says what ran (an X11 test container).

When a run passes §G, record it here or in a new sheet, and change both files
to match the cells that passed.
